# Eval Split Guard 产品规格

[English](PRODUCT_SPEC.md)

## 问题证据

评测框架已经把去污染和稳定样本身份作为真实运维问题。[lm-evaluation-harness 去污染指南](https://github.com/EleutherAI/lm-evaluation-harness/blob/main/docs/decontamination.md)记录了重叠检查，而 [Inspect AI datasets](https://inspect.aisi.org.uk/datasets.html) 将样本标识作为评测数据的一等字段。团队仍然需要一个在评测开始前运行的小型、确定性预检工具。

## 产品决策

构建一个只审计调用方显式清单的本地 CLI。精确相等和显式分组可复现、可行动。语义相似、训练数据归因、数据集下载和自动重新划分不在产品边界内。

## Version 1 清单

每条 UTF-8 JSONL 记录都是严格对象：

- `schema_version`：整数 `1`。
- `split`：非空字符串，最多 256 bytes。
- `sample_id`：非空字符串，最多 256 bytes；在所属 split 内唯一。
- `content` 与 `content_sha256` 必须且只能提供一个。
- `content`：非空字符串；SHA-256 使用其精确 UTF-8 bytes。
- `content_sha256`：恰好 64 位小写十六进制字符。
- `group_id`：可选非空字符串，最多 256 bytes。
- 拒绝未知字段。

泄漏对是无方向的，必须通过可重复的 `--leakage-pair FROM:TO` 参数显式提供。不报告未声明关系中的跨 split 重复。每个被引用的 split 都必须至少出现在一条有效记录中，否则调用不完整并以 `2` 退出。

## 输出与退出码

文本和带版本的 JSON 输出只包含文件名、计数、行号、固定代码、严重性和固定消息。禁止输出内容、标识、分组、hash 和绝对路径。

- `0`：完整审计且没有发现。
- `1`：完整审计且存在至少一个发现。
- `2`：调用/输入无效，或全局资源上限阻止完成审计。

README 表格中的发现代码和严重性是规范定义。

## 资源契约

- 只接受普通文件；拒绝符号链接和非文件。
- 输入文件最大 64 MiB。
- 单条 JSONL 记录最大 1 MiB；超限记录产生 `ESG001`，排空该行后继续扫描。
- 最多 100,000 条记录。
- 最多 10,000 条诊断。
- 估算跟踪内存上限 64 MiB。

超过全局限制时以退出码 `2` 失败关闭；截断证据后绝不返回干净或完整结果。

## 验收测试

- 干净清单。
- 区分畸形 JSON 与符合 JSON 语法但违反 schema 的记录。
- 同 split 样本重复。
- 同 split 精确内容与分组警告。
- 显式泄漏对中的内容与分组错误。
- 忽略未声明关系中的跨 split 重复。
- 原始内容与小写预哈希等价。
- 拒绝大写或畸形 hash。
- 排空超限记录并继续。
- 拒绝符号链接、隐私安全输出、稳定 JSON schema，以及退出码 `0`、`1`、`2`。

## 明确不做

不联网、不提供数据集适配器、不执行评测、不做模糊或语义匹配，不调用 embedding 或 LLM，不自动修复/重新划分，也不声称能够证明模型训练污染。
